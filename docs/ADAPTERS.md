# Контракты подключений

## Модель

По умолчанию `MODEL_PROVIDER=mock`: внешних обращений к модели нет. Для своей модели установите `MODEL_PROVIDER=http`, `MODEL_ADAPTER_URL=https://your-adapter.example/draft`, при необходимости `MODEL_API_KEY`. Перезапустите `docker compose up -d --force-recreate rag-api`.

Это URL **вашего адаптера**, а не произвольный стандартный endpoint вендора. RagChat отправляет POST JSON:

```json
{
  "question": "Вопрос сотрудника",
  "history": [],
  "documents": [{"source":"manual.pdf","page":1,"text":"фрагмент","score":0.5}],
  "expertKnowledge": [{"id":"entry","question":"вопрос","answer":"согласованный ответ"}],
  "webSources": [{"url":"https://example.org","title":"Источник","text":"найденные сведения"}],
  "searchStatus": "ok",
  "instructions": "Инструкции по синтезу и обращению с источниками"
}
```

Ответ адаптера:

```json
{"text":"Цельный законченный ответ без списка источников", "metrics":{"promptTokens":100,"completionTokens":80,"totalTokens":180,"llmMs":1500}}
```

`text` обязателен. Адаптер отвечает за преобразование в нужный протокол модели, переданные инструкции по синтезу цельного ответа. Заголовок авторизации `Bearer MODEL_API_KEY` используется, только если ключ задан. Рекомендуется HTTPS; HTTP допускается для собственного изолированного локального сервиса. Не передавайте ключи в URL. Тайм-аут 55 секунд, перенаправления не выполняются. Ошибка модели не маскируется под ответ: очередь получает сообщение о необходимости ручной подготовки.

## Интернет-поиск

Без `SEARCH_ADAPTER_URL` сетевого поиска нет; модель получает `searchStatus=not_configured`. Для подключения задайте URL собственного поискового адаптера и необязательный `SEARCH_API_KEY`.

POST `{"query":"вопрос"}` → `{"sources":[{"url":"https://example.org/page","title":"Заголовок","text":"Проверенный фрагмент"}]}`.

RagChat принимает максимум 8 источников HTTP(S), затем передаёт их вместе с внутренним контекстом модели. При ошибке передаётся `unavailable`, при пустом результате — `empty`; отсутствие результатов не выдаётся за отсутствие информации в мире. Каталог доменов в интерфейсе служит для пометок источников и не ограничивает весь интернет. Поисковый адаптер отвечает за поиск/чтение страниц, SSRF-защиту, соблюдение лимитов и точность цитирования. Текст источников является недоверенными данными.

## Retrieval и маршрутизация

`retrieve()` в `rag-service/main.py` — точка замены лексического поиска на векторный или гибридный. Возвращает `(documents, expertKnowledge)`; API и UI не зависят от движка. Экспертные знания индексируются отдельно от PDF.

Направления универсальны: `GENERAL` и `SPECIALIST`. `SPECIALIST_KEYWORDS` — список ключевых фраз через запятую, по умолчанию пуст. Для отраслевого классификатора замените реализацию `/v1/classify`, сохранив `reviewPool`, `confidence`, `reason`, `method`.

Документы и экспертные ответы передаются во внешний модельный адаптер только после явного включения HTTP-режима. Внешний поиск получает текст вопроса. Организация сама определяет допустимые данные и провайдеров.
