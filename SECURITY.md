# Безопасность и публикация

- Не добавляйте в Git `.env`, ключи, пользовательские данные, PDF, индексы, логи, дампы и каталоги runtime.
- Первый администратор создаётся из секретных переменных окружения; общедоступных demo-аккаунтов нет. Пароли хранятся как bcrypt-хэши.
- Используйте собственные SMTP/VAPID/model/search credentials. Внешние интеграции по умолчанию отключены. Не направляйте адаптеры на чужую корпоративную инфраструктуру.
- По умолчанию только UI доступен на loopback. Для production используйте TLS, сетевые ограничения и ограничение попыток входа на reverse proxy. Встроенного rate limiter/MFA/SSO пока нет.
- Не масштабируйте Node API в несколько процессов без доработки согласованности кэша и фоновых задач.
- PDF обрабатывается локальным парсером, без OCR. Для загрузок из недоверенного интернета добавьте изоляцию парсера, антивирусную проверку, ограничения CPU/RAM и времени.
- SQLite RAG и PostgreSQL содержат пользовательские сведения. Настройте резервное копирование, сроки хранения и восстановление вне приложения.
- Не публикуйте полный журнал инцидента с персональными данными или секретами. При сообщении об уязвимости используйте приватный канал владельца вашего форка.
- MIT-файл определяет предлагаемые условия распространения; право на исходный код и сторонние материалы подтверждает публикующий владелец.
